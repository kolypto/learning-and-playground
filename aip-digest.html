Design Foundations 3

AIP-111

Planes (CPL / DPL)

Separate the management plane (provision resources) from the data plane (use them).

text
Management: CreateTopic, DeleteTopic
Data:       Publish,     Subscribe
Key points
  • Management plane = CRUD on config, resource-oriented
  • Data plane = high-throughput data access
  • Different latency/consistency expectations
  • Keep them in separate services when they diverge
  • CPL / DPL = Yandex Cloud jargon for these (not AIP terms)

Resources 7

AIP-121

Resource-oriented design

Model the API as resources (nouns) + a small set of standard methods (verbs).

text
publishers/{publisher}/books/{book}
  Get · List · Create · Update · Delete
Key points
  • Prefer 5 standard methods over custom RPCs
  • Resources have name, type, methods
  • Collections nest hierarchically
  • Custom methods only when nothing standard fits
approved aip.dev/121 ↗
AIP-122

Resource names

Each resource is identified by one opaque hierarchical `name` — collection/id pairs alternating all the way down.

text
publishers / oreilly / books / 9781492 / chapters / 3
  └coll┘   └─id─┘  └coll┘  └──id──┘  └─coll─┘ └id┘

name = collection/{id}/collection/{id}/…
Key points
  • Strictly alternates collection/id/collection/id
  • Collection segments: plural, lowerCamelCase
  • IDs are opaque — clients don't parse or build names
  • `name` field holds identity; `parent` holds container
  • Avoid PII / user-invisible IDs in names
approved aip.dev/122 ↗

AIP-131

Standard methods: Get

Fetch a single resource by name. Read-only, no side effects.

http
GET /v1/publishers/oreilly/books/9781492

→ 200  { "name": "publishers/oreilly/books/9781492", … }
→ 404  NOT_FOUND
Key points
  • Request has a single required `name`
  • Returns the resource or NOT_FOUND
  • No side effects; safe to retry
  • No `filter`/`order_by` — that's List
approved aip.dev/131 ↗
AIP-132

Standard methods: List

Return a page of resources from one collection under a `parent`.

http
GET /v1/publishers/oreilly/books
      ?pageSize=20&pageToken=abc&orderBy=title

→ { "books": [ … ], "nextPageToken": "def" }
Key points
  • Response MUST include next_page_token
  • Optional filter (AIP-160) & order_by
  • Optional total_size (post-filter, may estimate)
  • Consistent for any reader with permission
approved aip.dev/132 ↗
AIP-133

Standard methods: Create

POST a new resource into a collection under `parent`.

http
POST /v1/publishers/oreilly/books?bookId=9781492
{ "title": "A Wizard of Earthsea" }

→ 200  { "name": "publishers/oreilly/books/9781492", … }
Key points
  • Request: parent + resource (+ optional id)
  • Server assigns name if id not given
  • Returns the created resource
  • Support client-specified id for idempotency
approved aip.dev/133 ↗
AIP-134

Standard methods: Update

PATCH a resource; an update_mask says which fields to touch.

http
PATCH /v1/publishers/oreilly/books/9781492
      ?updateMask=title,rating
{ "title": "New Title", "rating": 5 }
Key points
  • PATCH = partial via field mask (AIP-161)
  • Mask absent → full replace (discouraged)
  • Support allow_missing for upsert
  • OUTPUT_ONLY fields ignored in mask
approved aip.dev/134 ↗
AIP-135

Standard methods: Delete

DELETE a single resource by name. Returns empty (or an LRO).

http
DELETE /v1/publishers/oreilly/books/9781492

→ 200  {}          (or an Operation if long-running)
Key points
  • Single required `name`
  • Not idempotent by default → use etag / allow_missing
  • Cascading deletes need explicit force flag
  • Soft delete → see AIP-164
approved aip.dev/135 ↗
AIP-136

Custom methods

Non-CRUD actions via the colon syntax: `resource:verb`.

http
POST /v1/publishers/oreilly/books/9781492:archive
{}

// collection-level verb:
POST /v1/publishers/oreilly/books:sort
Key points
  • Verb is lowerCamelCase after ':'
  • Default POST; GET only if safe & cacheable
  • Attach to a resource or a collection
  • Last resort — try standard methods first
approved aip.dev/136 ↗
AIP-157

Partial responses

Return only some fields via a field-mask query param or a view enum.

http
GET /v1/publishers/oreilly/books/9781492?$fields=name,title

// or a preset view:
GET /v1/publishers/oreilly/books?view=BASIC
Key points
  • Mask goes in a side channel (query param / header), NOT the request body
  • Field mask as a request field is discouraged
  • Omitted mask defaults to '*' (all fields)
  • View enum (BASIC / FULL) for fixed presets
approved aip.dev/157 ↗
AIP-158

Pagination

Standard page_size / page_token in, next_page_token out.

text
req:  page_size, page_token
resp: results[], next_page_token
Key points
  • Opaque page_token — clients don't build it
  • Empty next_page_token = last page
  • page_size is a max, server may return fewer
  • Token encodes filter/order; don't mix params
approved aip.dev/158 ↗
AIP-159

Reading across collections

Use `-` as a wildcard parent to List across sibling collections.

http
GET /v1/publishers/-/books

Key points
  • `-` wildcard in the parent segment
  • Read-only aggregation
  • Filtering still applies

AIP-160

Filtering

A single string `filter` field with a standard expression grammar.

text
filter = rating > 4 AND NOT hidden
         author.name = "Le Guin"        (nested field)
         metadata.tags : "fantasy"       (map / has)
         details.pages.count >= 300      (deep nesting)
Key points
  • One string field, EBNF-defined grammar
  • Nested fields via dotted paths (author.name)
  • `:` = has/contains; `=` exact match
  • AND OR NOT, comparisons, ( ) grouping
  • Document which fields are filterable
approved aip.dev/160 ↗
AIP-161

Field masks

FieldMask names exactly which fields a request reads or writes.

text
update_mask = "title,author.name"
(FieldMask, dotted paths)
Key points
  • Dotted paths into nested messages
  • '*' means all fields
  • Drives partial update (AIP-134) & read (AIP-157)
approved aip.dev/161 ↗
AIP-164

Soft delete

Delete marks resources deleted; undelete restores; expunge purges.

http
DELETE /v1/publishers/oreilly/books/9781492      (soft)
GET    /v1/publishers/oreilly/books?showDeleted=true
POST   /v1/publishers/oreilly/books/9781492:undelete
POST   /v1/publishers/oreilly/books/9781492:expunge  (hard)
Key points
  • Soft-deleted keep a delete_time
  • List with ?showDeleted=true to include them
  • undelete within the retention window
  • expunge for permanent removal
approved aip.dev/164 ↗
AIP-165

Criteria-based delete

Delete many matching a filter via `:purge` (an LRO), with a dry-run guard.

http
POST /v1/{parent=publishers/*}/books:purge
body: { filter:"…", force:true }
Key points
  • Filter selects what to delete
  • force=false → dry-run count first
  • Returns an LRO
  • Dangerous — guarded by design
